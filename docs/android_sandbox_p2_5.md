# Android PRoot sandbox (P2-5)

Status: implemented in the app (2026-11-12). Scope is the plan's Android
subset: one **foreground** `shell_exec` command inside a pinned Ubuntu Base
rootfs, plus the shared host↔guest mount table used by the shell and prompt.
The shell is **arm64-v8a only**; `armeabi-v7a` and `x86_64` can run the rest of
the app, but the PRoot executables and `libandroid-shmem` are packaged only
under `lib/arm64-v8a/`.
The shared arm64 rootfs asset is present in every install but unusable because
the native probe rejects non-arm64 processes. PTY sessions, background jobs,
and the mobile in-app terminal are deliberately out of scope.

## What ships

| Artifact | Path | Pin |
|:--|:--|:--|
| PRoot exec | `android/app/src/main/jniLibs/arm64-v8a/libproot_exec.so` | Termux `proot 5.1.107.102`, SHA-256 `10a394b585c2fc2b2c8502544f4e5f1be581dc8bfff79e8ba62f16207423e030` |
| PRoot loader | `android/app/src/main/jniLibs/arm64-v8a/libproot_loader.so` | same Termux package |
| libandroid-shmem | `android/app/src/main/jniLibs/arm64-v8a/libandroid-shmem.so` | `0.7`, SHA-256 `0da3a24d558b93c92bcf8d611e0826a99ff96e396b148e6cdf33b47c47c57ff6` |
| libtalloc | `android/app/src/main/assets/sandbox/lib/libtalloc.so.2` | `2.5.0`, SHA-256 `556591f43bb773ad8777e1a29522640866a55f95dab71914418b94a8c58ad5a7` |
| Ubuntu Base rootfs | `android/app/src/main/assets/sandbox/rootfs-ubuntu-base-24.04.4-arm64.tgz` | Ubuntu Base 24.04.4 arm64, SHA-256 `04207713ece899c3740823d33690441ad3a7f0ded1101aca744e2b0f37ac7ff2` |
| Manifest | `android/app/src/main/assets/sandbox/manifest.json` | tracked; `RootfsInstaller` verifies the rootfs SHA at install time |

The binary/rootfs payloads are intentionally **not committed** (`.gitignore`).
They are generated by:

```bash
cd android
bash scripts/fetch-sandbox.sh
```

The script verifies every SHA-256 against the pins above. Gradle's
`ensureSandboxFetched` task runs before `preBuild` and fails loudly when a
payload is missing, so a release APK cannot silently lose the sandbox.

`android/app/build.gradle.kts` sets `jniLibs.useLegacyPackaging = true`
(native libs are extracted to `nativeLibraryDir`, where Android permits
execution) and marks `.tgz` as `noCompress` (AAPT2 would otherwise deflate the
already-compressed archive). The rootfs filename avoids `.tar.gz` because
AAPT2 special-cases `.gz` assets.

## Architecture

| Layer | File | Responsibility |
|:--|:--|:--|
| Path/mount table | `lib/core/services/shell/android/workspace_mount_table.dart` | host↔guest mapping; `/workspace`; `..`/NUL/escape rejection; bind list for PRoot |
| Host probe | `lib/core/services/shell/android/workspace_path_probe.dart` | directory/list/read/write/delete probe; rejects `content://`; FUSE/noexec is not a failure |
| Native channel | `lib/core/services/shell/android/android_sandbox_service.dart` | `probe`/`install`/`cancelInstall`/`remove`/`run`/`cancel`/`diskUsage`; progress and output events |
| Tool backend | `lib/core/services/shell/android/android_shell_service.dart` | `shell_exec` schema, approval defense, 30 s default / 600 s cap / -1 unlimited, output shaping/externalization, changed-file snapshot |
| Android plugin | `android/app/src/main/kotlin/com/psyche/omnichat/sandbox/SandboxPlugin.kt` | MethodChannel `omnichat/sandbox`; one install/run at a time |
| Installer | `.../RootfsInstaller.kt` | five-stage install: stream+hash → extract → patch/validate → atomic rename → cleanup; marker `metadata.json` |
| Extractor | `.../SafeTarExtractor.kt` | ustar/PAX/GNU-longname; traversal and symlink-escape rejection; no `java.nio.file` |
| PRoot argv | `.../ProotCommand.kt` | independent argv command, `env -i`, guest path validation, `/proc` fakes, `--kill-on-exit` |
| Runner | `.../ProotRunner.kt` | pipe draining, 24 KB/6 KB native caps, timeout/cancel, SIGQUIT-first + process-tree sweep |

The rootfs is installed under `{appData}/cli_runtime/rootfs/`; the workspace is
a separate bind at guest `/workspace`. File tools continue to use host paths;
the prompt tells the model that `shell_exec` uses the guest `/workspace`.

## Behavior and limits

- **Foreground only, one command at a time.** Closing the app may stop a
  running command. Background jobs are not part of the product contract.
- **Not a security sandbox.** Commands run with the app's permissions and can
  access the bound workspace. The approval switch is the product gate.
- **Shared-storage workspaces** are read/write but have no executable bit and
  no symlink support (FUSE/sdcardfs). The probe does not fail for this; the
  prompt and Settings page explain it.
- **Timeout/output:** default 30 s, hard 600 s; `-1` means unlimited; stdout 24 KB + stderr 6 KB in
  the model-facing payload, with the shared 68 KB tool-result cap. Larger
  output is externalized to the read-only session-outputs zone.
- **Rootfs / ABI:** Ubuntu Base 24.04.4 arm64 only. `shell_exec` is not
  advertised on `armeabi-v7a`, `x86_64`, non-Android platforms, or before the
  rootfs probe is ready. The universal APK still installs and runs the rest of
  the app on `armeabi-v7a` and `x86_64`; the shared arm64 rootfs asset is
  present but unusable there.
- **No LLM-controlled rootfs source.** The rootfs URL/hash lives only in the
  build script; the runtime accepts only the packaged asset.

## F-Droid / GPL compliance

- PRoot is **GPL-2.0-or-later**. The app redistributes the unmodified Termux
  binaries. Corresponding source: <https://github.com/proot-me/proot>; the
  exact Termux packaging recipe is
  <https://github.com/termux/termux-packages/tree/master/packages/proot>.
  The binaries are separate, independently launched programs; the AGPL app
  code is not a derivative of PRoot.
- `libtalloc` is **LGPL-3.0-or-later** and is shipped as a replaceable shared
  library (`libtalloc.so.2`). Source: <https://gitlab.com/samba-team/talloc>.
- `libandroid-shmem` is **Apache-2.0**: <https://github.com/termux/libandroid-shmem>.
- The Ubuntu Base rootfs is redistributed under Ubuntu's licence terms; the
  image contains per-package licences under `/usr/share/doc`. Source URL and
  SHA-256 are pinned above.
- `android/scripts/fetch-sandbox.sh` is the reproducible build entry point for
  every bundled artifact. `THIRD_PARTY_NOTICES.md` carries the user-facing
  attribution, and Settings → Android Shell points to it.
- `MANAGE_EXTERNAL_STORAGE` remains necessary only because the existing
  workspace picker exposes real shared-storage paths; app-private workspaces
  work without it. The shell does not request `content://` URIs.
- The shell is foreground-only; the app does not promise background command
  completion or background package installs.

## Verification

```bash
flutter gen-l10n
flutter analyze --no-pub
flutter test test/android_workspace_mount_table_test.dart \
  test/android_workspace_path_probe_test.dart \
  test/android_shell_service_test.dart
cd android && JAVA_HOME=<jdk-17> ./gradlew :app:compileDebugKotlin :app:testDebugUnitTest
```

Real-device smoke (arm64 Android): install the rootfs from Settings → Android
Shell, run `echo`, `ls`, `cat /etc/os-release`, verify a timeout, a cancel, and
an external workspace read/write (the latter must report the noexec/symlink
limits when a script/symlink is attempted). This is a release gate, not a
prerequisite for the Dart/Kotlin unit checks above.
